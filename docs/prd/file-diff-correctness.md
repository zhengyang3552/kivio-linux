# 仅修复文件diff统计夸大

用户在大回退后明确追加要求：修复六处局部修改被报告为上千行增删的问题。本次基线`2bde8ac3`，仅修改diff计算及必要依赖和测试，不重新加入已撤回的上下文、提示词、文件落盘或执行策略。

根因：原LCS算法在中段行数乘积超过250000时，不再寻找公共行，而把整个中段当成删除和新增。真实edit回归中磁盘内容正确，但预期30/20被报告为1113/1103。

修复：以Myers行差异计算替代整段降级，沿用既有统一diff格式和分组。完全没有公共行的重写直接输出精确删除/新增，避免这一常见退化输入浪费计算。不设置会返回粗略结果的超时，不新增统计协议字段。

验收：真实六处edit产生6个hunk、30行新增/20行删除，磁盘内容及CRLF保持正确；空文件、重复行的最小增删数与独立LCS参考比较；10000行完全重写统计准确。原有文件测试和全量测试通过（已有平台失败单列）。

依赖API来源：[similar 2.7 capture_diff_slices](https://docs.rs/similar/2.7.0/similar/fn.capture_diff_slices.html)、[Myers实现及复杂度](https://docs.rs/similar/2.7.0/similar/algorithms/myers/index.html)。Myers仍存在高差异且部分相同的大输入最坏情况；本次没有声称任意大小文件的固定耗时上限。

验证：原回归先失败（1113/1103），修复后33项文件测试全部通过（含30/20、6个hunk的真实edit）。全量Rust测试2387通过、3失败、45忽略；两项为既有Windows路径断言，另一项未改动的HTTP hook成功测试单独复核通过。新测试二进制最初缺Common-Controls外部清单，已按项目既有清单补齐并刷新二进制时间戳后正常运行；未修改构建脚本。Standards与Spec复审均无剩余发现。开发应用已自动重新编译运行；历史保存的旧diff不自动重算。
